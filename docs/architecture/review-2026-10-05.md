# Architecture Review, 5 Oct 2026

A fresh-context adversarial review of the plan's architecture (sections 4-17), the ADRs, the v1 audit, `PRODUCT.md`, the console brief and the week-1 code. It was run as an independent agent so it would not inherit the builder's assumptions. Its claims were spot-checked: MinIO's archived status was confirmed with the GitHub API (`archived: true`, last release October 2025).

## Bottom line

The direction is sound. But the headline claims rest on things the design did not yet guarantee:

- Byte-identical replay is impossible while ticks, rule changes, operator actions and assignments reach the processor outside the recorded input.
- The alert lifecycle had two writers.
- The domain state shape would not survive a real state store.
- MinIO is archived.

## Findings

| # | Sev | Finding | Decision |
| --- | --- | --- | --- |
| 1 | Critical | Replay can't be byte-identical: debounce, escalation and evidence depend on when ticks, rules, acks and assignments arrived, and none of that ordering is recorded | ADR-0005: one ordered input log |
| 2 | Critical | Two writers own the alert lifecycle (the processor and operators via the outbox); the version guards can't reconcile them | ADR-0006: the processor is the single owner |
| 3 | Critical | Alert IDs are random, and output IDs collide within a minute | ADR-0015: uuid5(causing record, ordinal) |
| 4 | High | The domain state is one immutable value per vehicle, copied and re-serialised on every event; buckets never evict | ADR-0016: delta interface, a key per bucket, eviction on event-time progress |
| 5 | High | Dedup is keyed by boot_id alone, not (device_id, boot_id) | Fix in the domain; boot_id must be random |
| 6 | High | The gateway's "sequence regression" rule quarantines every buffered replay and retransmit | Stateless gateway; reuse detection moves to the processor |
| 7 | High | Rules assume a reading every minute; real reefer telematics report every 1-15 min, with bursts on alarm | Rules over event-time durations with sample guards; reporting rate is an owner question |
| 8 | High | No path for reference data (cargo profiles, assignments) into the processor | ASSIGNMENT_CHANGED records on the input log |
| 9 | High | Shipment-keyed risk conflicts with vehicle-keyed state | ADR-0017: every output keyed by vehicle_id |
| 10 | High | Quix Streams has no timers, no state scans, and best-effort multi-topic ordering | No `concat`, no Quix windows; ticks in-band; week-2 spike criteria below |
| 11 | High | librdkafka's default partitioner differs from murmur2 tooling, which silently splits a vehicle's state | ADR-0017: one producer factory pinning murmur2_random |
| 12 | High | A partition watermark is shared by ~2,000 trucks and one fast device clock poisons it | No watermark; lateness = ingest_time − event_time per record |
| 13 | High | MinIO is archived (confirmed) | ADR-0013 (amended): SeaweedFS |
| 14 | High | "Byte-identical" was undefined | ADR-0015: determinism contract |
| 15 | High | Replaying "a stored day" has no defined starting state | Replay from the run epoch; snapshots out of scope |
| 16 | Medium | Alerts pushed from the topic race the Postgres projection | Push after projection (LISTEN/NOTIFY) |
| 17 | Medium | WebSocket resume semantics unspecified | ADR-0018: (epoch, seq) for gap detection; resync = snapshot |
| 18 | Medium | Per-client filtering in Python won't keep up at 25k vehicles | ADR-0018: binary columnar tile frames, one encode per tile |
| 19 | Medium | Postgres write load at benchmark scale | `telemetry.minutes.v1`; throttled `vehicle_state`; no `processed_events` for telemetry-rate topics |
| 20 | Medium | DuckDB is single-writer: the API reading Gold collides with `dbt build` | Remove the API→DuckDB path |
| 21 | Medium | Exposure is implemented twice (processor and dbt) | State the tolerance and test it |
| 22 | Medium | The archiver's idempotency is unspecified | Offset-named Parquet files, partition hour from record ingest_time |
| 23 | Medium | Dev-mode broker durability may be hollow | Chaos runs with fsync on; scope the claim |
| 24 | Medium | Mixing the virtual and wall clocks breaks scenario evaluation | Run criteria 4-5 in-process on the virtual clock |
| 25 | Medium | Rule activation through a compacted topic is non-deterministic | RULES_ACTIVATED records into every input partition |
| 26 | Medium | Console full-fleet replay has no backend | A minute-resolution fleet history endpoint from `minute_series` (kept: it's the console's signature interaction) |
| 27 | Medium | The console contract is shaped for full frames, with client-side risk | Snapshot + deltas; risk from the server only; provisional estimator labelled |
| 28 | Medium | JWT with refresh tokens is too much for a same-origin SPA | ADR-0008: session cookie; WebSocket ticket from the session |
| 29 | Medium | The hash-chained audit log forks under concurrency; JSONB hashing is unstable | Advisory lock; hash canonical bytes (JCS), not JSONB |
| 30 | Low | Tenancy is half-done; vehicle ID types are mixed | org_id in payloads only; text vehicle IDs everywhere |
| 31 | Low | Banker's rounding on floats at the domain boundary | Explicit half-up quantisation (ADR-0015) |
| 32 | Low | The architecture image and the text disagree on the archiver's source | Archive the input log; drop `telemetry.clean.v1` |

## Week-2 stream-engine spike: pass/fail criteria

| # | Measure | Pass |
| --- | --- | --- |
| S1 | Sustained throughput per process | ≥ 5k events/s at under one core |
| S2 | 200 random SIGKILLs during duplicate_storm plus buffered replay | Final canonical state hash equals a no-crash run, 200/200 |
| S3 | Changelog recovery, 1k vehicles with 48 h of buckets | Restored in ≤ 60 s with an equal state hash |
| S4 | Rebalance when a second instance joins | Pause ≤ 10 s, no state mismatch |
| S5 | In-band ticks | TELEMETRY_GAP within 2 ticks; byte-identical output under two PYTHONHASHSEEDs |
| S6 | 45-minute buffered replay interleaved with live data | True event-time start on the alert; live T2 p99 grows less than 2× |
| S7 | exactly-once versus at-least-once | Record the latency delta; adopt if p99 cost is under 1 s |
| S8 | Replay throughput from re-produced Bronze | 24 h × 1k trucks in ≤ 30 min |

If Quix Streams fails S2 or S5, Plan B is a hand-rolled confluent-kafka loop that keeps state and consumer offsets in one SQLite transaction. Flink is not a realistic fallback for a solo build.

## Frontend guidance adopted

- deck.gl renders vehicles from day one (binary attributes, columns for 3D), with MapLibre for the basemap only. Dead reckoning runs on the GPU from (p0, velocity, t0).
- 3D terrain becomes a stretch goal; 3D means pitch plus extruded signal posts.
- The WebSocket worker posts transferable structure-of-arrays buffers at most once per animation frame. Per-vehicle state never enters React.
- The lanes board draws tags only for non-Clear shipments once a lane is crowded; Clear ones become ticks.
- Docs and the case study share one Astro Starlight site, replacing MkDocs, so there are not three web surfaces.

## Owner questions raised

Reporting interval; what the 25k target is for; whether shipments change trucks; the scope of "byte-identical"; phone parity scope and terrain; public hosting; multi-tenancy; MQTT's place in the story; the 48-hour lookback; notifier depth.
